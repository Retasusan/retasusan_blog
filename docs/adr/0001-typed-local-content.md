# 0001: 掲載内容を型付きのローカルデータとして管理する

- 状態: Superseded by [0005](0005-markdown-content-management.md)
- 日付: 2026-10-30

## 背景

このサイトの主目的は、制作物・活動・学習経験を継続的に追加できる個人ポートフォリオである。項目を増やすたびにページの JSX を編集する構造では、内容の更新と表示の変更が混ざる。既存ブログは microCMS に依存しているが、ポートフォリオの更新に CMS の準備は必要としたくない。

## 決定

`src/content/` に掲載内容を集約し、ドメインごとに分ける。

- `profile.ts`: 自己紹介・関心・外部アカウント
- `projects.ts`: 制作物。配列の順番が表示順
- `activities.ts`: 職務・イベント・制作・学習の記録。配列の順番が表示順
- `skills.ts`: 技術のグループ
- `sections.ts`: ページの構成と表示設定
- `types.ts`: 共有するデータの型

通常の追加は、対応する配列にオブジェクトを追加するだけで完結させる。ID はタイトルから生成せず、安定したアンカーとして明示する。活動の日付は ISO 形式で一度だけ持ち、表示をそこから導出する。

制作物の説明・画像・専用イラストは任意とする。画像も専用イラストもない場合は汎用カバーを表示するため、新しい制作物に合わせてコンポーネントを作る必要はない。リンクは配列にして、ソースコード・公開サイト・資料などを同じ仕組みで追加できるようにする。

掲載する事実は既存プロフィールとリンク先の公開リポジトリを根拠とする。成果の数値や担当範囲を推測して補わない。コンセプトイラストには `CONCEPT VISUAL` と明記し、実画面のスクリーンショットと区別する。

## 検討した選択肢

- JSX 内に直接書く: 初期実装は容易だが、項目の追加が UI の変更を伴う。
- 既存 microCMS に追加する: ブラウザから編集できる一方、スキーマ・認証情報・API の運用が増える。
- Markdown / MDX: 長文の実績紹介に適するが、短い構造化データにはパースやプラグインの追加が必要になる。
- 型付き TypeScript: 既存の開発環境で型チェックと補完が使え、追加依存なしで構造を表現できる。

## 影響とトレードオフ

- 掲載内容だけを変更する場合、ページや CSS の編集は不要。
- 変更内容を Git の差分でレビューでき、外部 API への接続なしでトップを表示できる。
- 内容の公開にはビルド・デプロイが必要。ブラウザからの編集画面は提供しない。
- 長文のケーススタディが増えたら、一覧用データと本文の保管方法を分ける判断を別 ADR で行う。
