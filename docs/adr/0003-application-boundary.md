# 0003: 既存の Next.js 内でポートフォリオと記事アーカイブを分離する

- 状態: Superseded by [0007](0007-vue-nuxt-migration.md)
- 日付: 2026-10-30

## 背景

作業対象は Next.js の既存ブログのリポジトリであり、サイトの目的がポートフォリオに移った。記事には既存 URL がある。ポートフォリオへの切り替えに合わせて、記事の消去や外部公開先の変更までは依頼されていない。

## 決定

- `/` はローカルデータだけで構成するポートフォリオにする。
- 共通のプロフィール・スキル・活動歴は `/about` でも同じデータと部品から表示する。
- `/articles`、`/articles/[articleId]`、`/notifications`、`/notifications/[notificationId]` は既存の microCMS を読む記事アーカイブとして保持する。
- ポートフォリオの主ナビはセクションへのリンクとし、記事はフッターの補助導線に置く。
- フレームワークとリポジトリは継続利用し、別プロジェクトの作成やホスティングの変更は行わない。

## 検討した選択肢

- 別リポジトリ・別サイトを作成: 独立運用しやすいが、いまの実行環境や公開先の移行が必要になる。
- ブログのルートを削除: コードは減るが、既存 URL や記事へのアクセスを失う。
- 同じアプリ内で責務を分離: 実行環境を維持しながら、トップの CMS 依存を外せる。

## 影響とトレードオフ

- ポートフォリオを確認するだけなら microCMS の環境変数は不要。
- 記事を表示するときは従来の `SERVICE_DOMAIN` と `API_KEY` が必要。
- 共通シェルはポートフォリオのものになり、記事ページも同じ配色・レイアウトを使う。
- ブログ関連の依存は残る。記事の移転・廃止は別の判断として扱う。
- 本番公開は別作業であり、この変更だけで外部サイトをデプロイしない。
