# 0002: セクションを独立させ、構成とナビゲーションを共有する

- 状態: Accepted
- 日付: 2026-10-30

## 背景

後から制作物や活動を追加するだけでなく、今後の関心や見せたい内容に合わせてページの順序や構成も変えたい。ページ本体とナビゲーションに構成を二重に書くと、非表示セクションへのリンクなどが生じる。

## 決定

`src/app/components/portfolio/` をポートフォリオの表示単位とする。

1. `Portfolio.tsx` は構成の組み立てを担当する。
2. `sections/` の各コンポーネントは一種類の内容を担当する。
3. `Section.tsx` はセクション見出し・番号・アンカーの共通枠を担当する。
4. `ProjectCard.tsx` と `ProjectVisual.tsx` は制作物の表示を担当する。
5. `Portfolio.module.css` と `Sidebar.module.css` でスタイルの適用範囲を分ける。

`src/content/sections.ts` の配列を構成の唯一の参照元とする。配列の順序で本文とナビゲーションを並べ、`enabled: false` の項目は両方から除く。表示番号も同じ配列から導出する。

セクション ID とコンポーネントの対応は型付きレジストリで表す。新しい種類を追加したときに実装漏れが型エラーになるようにする。通常の実績追加では、レジストリやセクションを変更しない。

導入部分はサイト全体の説明と `h1` を担うため固定とする。導入のボタンは有効なセクション設定からリンク先を選び、制作物を非表示にしてもリンク切れにしない。データを空にした場合は見出しと空状態を表示し、ナビゲーションのアンカーを保つ。

## 検討した選択肢

- 一枚の大きなページ: 追加時に別セクションへ影響しやすい。
- 個別ページに分割: 各ページを深く説明できるが、初見で全体像をつかむまでの移動が増える。
- 任意ブロックを組める汎用ページビルダー: 自由度が高いが、現在必要な種類に対して設定と検証が複雑になる。

## 影響とトレードオフ

- 項目の追加はデータ編集、構成の変更は設定編集、新しい表示の種類はコンポーネント追加として扱える。
- split layout は共有シェルで管理し、各セクションは左右の配置を意識しない。
- PC は左にプロフィールとナビ、右にコンテンツ。スマホは縦に並べる。
- 本文は Server Components で表示し、現在位置の追従など、ブラウザ機能が必要なナビだけを Client Component にする。JavaScript なしでも本文とアンカーリンクは使える。
- 新しいセクションの種類は、型・設定・レジストリ・コンポーネントの追加を伴う。任意の HTML をデータとして流し込む仕組みは設けない。

## Vue 移行後の実装

セクション分離とレジストリの判断は継続する。設定は `content/site.md`、コンポーネントは `app/components/portfolio/` の Vue SFC に移行した。詳細は [0005](0005-markdown-content-management.md) と [0007](0007-vue-nuxt-migration.md) を参照。
